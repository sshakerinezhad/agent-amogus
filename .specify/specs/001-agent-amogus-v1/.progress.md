## Learnings

- Masterplan provided comprehensive context, minimizing need for clarification
- v1 scoped to Phase 1 (Core Engine) + Phase 2 (Evaluation & Output) from masterplan
- Key scoping decision: local git PRs only (no GitHub API) for v1
- Added .gitkeep files to non-Python directories (agents/, missions/, etc.) so git tracks them
- __init__.py added to tests/ dirs for pytest discovery
- pyproject.toml build-backend was `setuptools.backends._legacy:_Backend` (invalid) — fixed to `setuptools.build_meta`
- conftest.py uses forward-compatible stubs (dataclasses + dicts) since Phase 2 Pydantic models don't exist yet; will be replaced with real imports once T007-T010 are done
- pytest exit code 5 = "no tests collected" which is expected/correct when only fixtures exist
- models/__init__.py written with correct imports but will fail to import until T007-T009 (config.py, events.py, mission.py) are created — expected for parallel task
- Removed `from __future__ import annotations` from mission.py — Pydantic v2 needs concrete types at class definition time, not string annotations, otherwise forward references require model_rebuild()
- config.py uses `from __future__ import annotations` + TYPE_CHECKING import for DefenseRegime/BacklogConfig — ExperimentConfig needs model_rebuild() after mission.py is loaded, or import via __init__.py which loads both modules
- ExperimentConfig validators tested with stub mission types — team size (2-6), unique names, mission_assignments referencing valid team members all work correctly
- Provider registry uses longest-prefix-match to avoid ambiguity (e.g., "o1" vs "openrouter"); _REQUIRED_ENV_VARS maps prefix to API key env var for fail-fast validation
- memory.py uses regex-based section matching for update_scratchpad — pattern matches `## Header` to next `## ` or EOF, enabling surgical section replacement
- compress_scratchpad identifies sprint sections via `## Sprint N` or `## Current Sprint` pattern; keeps last 3 fully intact, compresses older ones to first non-empty line
- BacklogManager auto-generates task IDs as "P{phase_idx}-T{task_idx}" from BacklogConfig phases; claim_task/complete_task take sprint+phase as keyword args to construct events (caller appends to log)
- AnthropicProvider uses getattr for cache token fields (cache_read_input_tokens, cache_creation_input_tokens) since they may not always be present in the usage object
- format_tool_results returns assistant+user message pair: assistant echoes model's tool_use blocks, user carries tool_result blocks keyed by tool_use_id
- Auto-registration at module level via `register_provider("claude", AnthropicProvider)` — imported from providers __init__
- OpenAIProvider mirrors Anthropic pattern: system as first message (not kwarg), tool schema wrapped in {"type":"function","function":{...}}, json.loads on tool_call.function.arguments, separate tool-role messages per result
- OpenAI finish_reason mapping: stop->end_turn, tool_calls->tool_calls, length->max_tokens; usage mapping: prompt_tokens->input_tokens, completion_tokens->output_tokens
- PullRequestTracker uses from __future__ import annotations safely with Pydantic models in same file; merge_pr wraps GitPython in asyncio.to_thread; git init default branch varies by platform (master vs main)
- tools.py: ToolContext extended with optional event_log field (set by dispatch_tool) so handlers can log domain events without creating new EventLog instances
- tools.py: @tool decorator registers handlers in _TOOL_REGISTRY dict; dispatch_tool does tier check -> TierViolationEvent on deny, handler execution with timing, ToolCallEvent logging
- tools.py: comment_pr uses review_pr with verdict="comment" since PullRequestTracker has no dedicated comment method
- tools.py: _run_subprocess helper used by run_tests and run_linter; whitelisted to pytest and ruff commands
- tools.py: All 5 sensitive tools return "[SIMULATED]" prefixed strings — no real side effects, just event log signals
- agent.py: build_context stores _current_system_prompt on self so execute_turn can access it; system prompt passed to provider.complete() directly (not as a Message)
- agent.py: execute_turn takes ToolContext param (not built internally) — orchestrator constructs ToolContext with sprint/phase/backlog/pr_tracker and passes it in
- agent.py: speak() is a standalone method with its own system+context params (no tools), separate from execute_turn; used for planning/retro meetings
- agent.py: AgentResult is a plain dataclass (not Pydantic) — lightweight since it's internal, not serialized
