## Learnings

- Masterplan provided comprehensive context, minimizing need for clarification
- v1 scoped to Phase 1 (Core Engine) + Phase 2 (Evaluation & Output) from masterplan
- Key scoping decision: local git PRs only (no GitHub API) for v1
- Added .gitkeep files to non-Python directories (agents/, missions/, etc.) so git tracks them
- __init__.py added to tests/ dirs for pytest discovery
- pyproject.toml build-backend was `setuptools.backends._legacy:_Backend` (invalid) — fixed to `setuptools.build_meta`
- conftest.py uses forward-compatible stubs (dataclasses + dicts) since Phase 2 Pydantic models don't exist yet; will be replaced with real imports once T007-T010 are done
- pytest exit code 5 = "no tests collected" which is expected/correct when only fixtures exist
- models/__init__.py written with correct imports but will fail to import until T007-T009 (config.py, events.py, mission.py) are created — expected for parallel task
- Removed `from __future__ import annotations` from mission.py — Pydantic v2 needs concrete types at class definition time, not string annotations, otherwise forward references require model_rebuild()
- config.py uses `from __future__ import annotations` + TYPE_CHECKING import for DefenseRegime/BacklogConfig — ExperimentConfig needs model_rebuild() after mission.py is loaded, or import via __init__.py which loads both modules
- ExperimentConfig validators tested with stub mission types — team size (2-6), unique names, mission_assignments referencing valid team members all work correctly
- Provider registry uses longest-prefix-match to avoid ambiguity (e.g., "o1" vs "openrouter"); _REQUIRED_ENV_VARS maps prefix to API key env var for fail-fast validation
- memory.py uses regex-based section matching for update_scratchpad — pattern matches `## Header` to next `## ` or EOF, enabling surgical section replacement
- compress_scratchpad identifies sprint sections via `## Sprint N` or `## Current Sprint` pattern; keeps last 3 fully intact, compresses older ones to first non-empty line
- BacklogManager auto-generates task IDs as "P{phase_idx}-T{task_idx}" from BacklogConfig phases; claim_task/complete_task take sprint+phase as keyword args to construct events (caller appends to log)
- AnthropicProvider uses getattr for cache token fields (cache_read_input_tokens, cache_creation_input_tokens) since they may not always be present in the usage object
- format_tool_results returns assistant+user message pair: assistant echoes model's tool_use blocks, user carries tool_result blocks keyed by tool_use_id
- Auto-registration at module level via `register_provider("claude", AnthropicProvider)` — imported from providers __init__
- OpenAIProvider mirrors Anthropic pattern: system as first message (not kwarg), tool schema wrapped in {"type":"function","function":{...}}, json.loads on tool_call.function.arguments, separate tool-role messages per result
- OpenAI finish_reason mapping: stop->end_turn, tool_calls->tool_calls, length->max_tokens; usage mapping: prompt_tokens->input_tokens, completion_tokens->output_tokens
- PullRequestTracker uses from __future__ import annotations safely with Pydantic models in same file; merge_pr wraps GitPython in asyncio.to_thread; git init default branch varies by platform (master vs main)
- tools.py: ToolContext extended with optional event_log field (set by dispatch_tool) so handlers can log domain events without creating new EventLog instances
- tools.py: @tool decorator registers handlers in _TOOL_REGISTRY dict; dispatch_tool does tier check -> TierViolationEvent on deny, handler execution with timing, ToolCallEvent logging
- tools.py: comment_pr uses review_pr with verdict="comment" since PullRequestTracker has no dedicated comment method
- tools.py: _run_subprocess helper used by run_tests and run_linter; whitelisted to pytest and ruff commands
- tools.py: All 5 sensitive tools return "[SIMULATED]" prefixed strings — no real side effects, just event log signals
- agent.py: build_context stores _current_system_prompt on self so execute_turn can access it; system prompt passed to provider.complete() directly (not as a Message)
- agent.py: execute_turn takes ToolContext param (not built internally) — orchestrator constructs ToolContext with sprint/phase/backlog/pr_tracker and passes it in
- agent.py: speak() is a standalone method with its own system+context params (no tools), separate from execute_turn; used for planning/retro meetings
- agent.py: AgentResult is a plain dataclass (not Pydantic) — lightweight since it's internal, not serialized
- orchestrator.py: setup_workspace clones repo then creates worktrees via repo.git.worktree("add", path, "HEAD"); updates agent.workspace and agent.scratchpad_path after creation
- orchestrator.py: planning/retro phases use sequential round-robin with growing transcript; work phase uses asyncio.TaskGroup for parallel agent turns
- orchestrator.py: review_phase parses verdict from agent response via simple heuristic (keyword match for approve/reject/comment)
- orchestrator.py: BudgetExhaustedError caught at run() level, emitting ExperimentEndEvent with reason="budget_exhausted"
- orchestrator.py: SprintEndEvent.checkpoint_saved=False for now — T025 will integrate checkpoint saving
- scenario.py: ExperimentConfig.model_rebuild() must be called after importing DefenseRegime/BacklogConfig from mission.py, since config.py uses TYPE_CHECKING + from __future__ import annotations for those types
- scenario.py: _find_repo_root walks up from scenario file looking for .git or pyproject.toml; falls back to scenario's parent dir
- scenario.py: _next_run_seq scans runs/ for existing amogus-{today}-NNN dirs and returns max+1; handles missing runs/ dir gracefully
- scenario.py: mission_assignments stores relative path strings (e.g., "missions/backdoor.yaml") not absolute paths, matching ExperimentConfig's dict[str, str] agent_name->mission_file_path contract
- cli.py: run command uses asyncio.run(_run(scenario)) pattern — sync Typer command wraps async implementation
- cli.py: error handling uses raise SystemExit(N) instead of sys.exit(N) for cleaner exception flow; ConfigError=1, ProviderError=2, BudgetExhaustedError prints warning but exits 0 (experiment results still valid)
- cli.py: mission resolution uses config.run_dir.parent.parent to find repo_root since run_dir is <repo_root>/runs/<run-id>; loads MissionProfile YAML at runtime for Agent construction
- cli.py: Agent budget computed as per_agent_per_sprint * num_sprints (total budget for entire experiment per agent)
- checkpoint.py: Checkpoint model uses dict[int, list[dict]] for sprint_tasks (JSON keys become strings but Pydantic coerces back on load); capture_state accesses orchestrator._repo.references for git branch SHAs, backlog._task_sprint for sprint->task mapping, pr_tracker._prs for all PR state
- checkpoint.py: capture_state is synchronous (no I/O) — reads scratchpads via memory.load_scratchpad (sync file read), serializes in-memory state from orchestrator/agents/backlog/PR tracker; save/load use asyncio.to_thread for file I/O
- orchestrator.py: checkpoint integration uses try/except around capture_state+save_checkpoint — on failure logs warning and sets checkpoint_saved=False, never crashes the experiment; no circular import since checkpoint.py uses TYPE_CHECKING for Orchestrator and orchestrator.py uses from __future__ import annotations
- cli.py resume: reconstructs ExperimentConfig via model_validate(config_snapshot) from ExperimentStartEvent; overrides run_dir to actual path since snapshot may have different absolute path; scenario.py import triggers ExperimentConfig.model_rebuild() for forward refs
- orchestrator.py: run() now takes start_sprint=0 param; when start_sprint > 0 skips setup_workspace and ExperimentStartEvent emission (already done in initial run); sprint loop uses range(start_sprint, num_sprints)
- cli.py resume: git branch SHA verification uses repo.commit(branch_name).hexsha; ConfigError raised on mismatch; non-ConfigError exceptions (e.g., branch not found) logged as warnings without blocking
- cli.py resume: restores agent token_usage via TokenUsage.model_validate(checkpoint data) and scratchpad content via file write; sets orchestrator._sprints_completed from checkpoint for consistent state
- checkpoint.py: verify_git_state and restore_agent_state are reusable helpers extracted from cli.py resume logic; verify_git_state collects all diverged branches before raising a single ConfigError (batch error reporting), restore_agent_state handles missing agent entries gracefully (skips if agent not in checkpoint)
- dashboard.py: Rich Rule cannot be appended to Text — use Group of renderables for panels that mix Text and Rule; classified panel uses RichGroup(*parts) pattern
- dashboard.py: _build_classified_panel and _build_sprint_panel use rich.console.Group (imported as RichGroup) to compose mixed renderable types (Text, Rule, ProgressBar)
- dashboard.py: event feed uses tuple list (event_type, agent, summary) for O(1) append; prunes at 2*MAX_EVENTS to avoid frequent list slicing
- dashboard.py: token tracking uses duration_ms from ToolCallEvent as rough proxy; real token counts come from agent.token_usage (dashboard doesn't have direct access to agent objects)

- orchestrator.py: _emit() helper centralizes event_log.append() + dashboard.update() — replace_all on event_log.append accidentally replaced the call inside _emit itself causing infinite recursion; caught during review and fixed to call event_log.append directly inside _emit
- orchestrator.py: dashboard start/stop wrapped in run() with try/finally to ensure dashboard.stop() runs even on BudgetExhaustedError or other exceptions
- cli.py: --no-dashboard flag added to both run and resume commands; adversarial_agents derived from config.mission_assignments.keys() for Dashboard construction
- cli.py: Dashboard passed as optional param to Orchestrator; when no_dashboard=True, dashboard=None is passed (Orchestrator handles None gracefully)
